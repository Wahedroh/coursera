# M4 ไลฟ์หน้าห้อง Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ครูเตรียม/สร้างกิจกรรมสด (เช็กอิน, โพล, WordCloud, ควิซ) เปิดไลฟ์บนจอโปรเจกเตอร์ นักเรียนในห้องตอบจากมือถือแบบเรียลไทม์ ได้ EXP

**Architecture:** D1 เป็นแหล่งความจริงทั้งหมด (`live_sessions`, `live_activities`, `live_responses`). ทุกการเปลี่ยนแปลงผ่าน HTTP → Worker เขียน D1 → คำนวณ snapshot 2 แบบ (ครู/นักเรียน) → ส่งให้ Durable Object `LiveRoom` (1 instance ต่อไลฟ์ ชื่อ `live:<id>`) กระจายผ่าน WebSocket hibernation. DO ไม่เก็บ state: ไคลเอนต์ดึง snapshot ทาง HTTP ทุกครั้งที่ (re)connect แล้วรับ `state` ที่ push มา จึงไม่ต้องพึ่งลำดับข้อความ และ DO รีสตาร์ตได้โดยไม่เสียอะไร

**Tech Stack:** Durable Objects (SQLite-backed, free plan), Hono, Drizzle/D1, React 19, qrcode-generator, vitest + Playwright

**Spec:** `docs/superpowers/specs/2026-10-25-classroom-assistant-design.md` §4 (live_*), §5.6, §6

## Global Constraints
- นักเรียนเข้าได้เฉพาะไลฟ์ของห้องตัวเองที่สถานะ `live`; ครูทุกไลฟ์
- 1 คำตอบต่อคนต่อกิจกรรม (unique activity_id+student_id); ตอบซ้ำ = 409 `already_answered`
- EXP: ตอบ +1 (`live`, ref = response id), ควิซถูก +2 (`live`, ref = `<response id>:correct`)
- ควิซ: เฉลยไม่ส่งให้นักเรียนจนกว่าจะเปิดแสดงผล; หมดเวลา (`opened_at + seconds`, เผื่อ 1 วินาที) = 409 `closed`
- WordCloud: คำ ≤ 30 ตัวอักษร, รวมคำซ้ำแบบไม่สนตัวพิมพ์/ช่องว่าง
- ห้ามส่งคำตอบรายคน/ชื่อนามสกุลเต็มให้นักเรียน (จอรวมแสดงชื่อเล่น=ชื่อจริงสั้นได้)
- D1 ≤ 100 ตัวแปรต่อคำสั่ง

## Review Focus
1. นักเรียนต่างห้อง/ไลฟ์จบแล้ว ตอบหรือเปิด WebSocket → 403/404
2. ตอบหลังครูปิดรับ/หมดเวลาควิซ → 409 ไม่ได้ EXP
3. ตอบพร้อมกันสองครั้ง (กดรัว) → บันทึกครั้งเดียว EXP ครั้งเดียว
4. snapshot นักเรียนไม่มีเฉลยควิซก่อนเปิดผล
5. WebSocket หลุดแล้วต่อใหม่ → ได้ state ล่าสุด

### Task 1: schema + shared
`src/server/db/schema.ts` (+migration), `src/shared/live.ts`, `tests/live-shared.test.ts`
- configs (zod discriminated by kind): checkin {prompt}, poll {prompt, options 2–6}, wordcloud {prompt}, quiz {prompt, options 2–4, correct, seconds 5–120}
- answer schemas: checkin {text 1–200}, poll/quiz {choice int}, wordcloud {word 1–30}
- `normalizeWord`, `aggregate(kind, config, responses)` → results; `studentView(snapshot)` strips quiz correct / results when hidden

### Task 2: API
`src/server/live/service.ts`, `teacher-routes.ts`, `student-routes.ts`, `tests/live-api.test.ts`
- Teacher: POST/GET `/classes/:id/live`, GET/PUT/DELETE `/live/:id`, POST `/live/:id/activities`, PUT/DELETE `/live/activities/:aid`, POST `/live/:id/move`, POST `/live/:id/start|end`, POST `/live/:id/goto {index}`, POST `/live/:id/accepting {open}`, POST `/live/:id/show-results {show}`
- Student: GET `/api/student/live/current`, GET `/api/student/live/:id`, POST `/api/student/live/:id/answer`

### Task 3: LiveRoom + WebSocket
`src/server/do/LiveRoom.ts`, `wrangler.jsonc`, `src/server/index.ts`, `tests/live-ws.test.ts`
- GET `/api/live/:id/ws` (Upgrade) — auth แล้ว forward ไป DO พร้อม role; DO `acceptWebSocket(ws, [role])`
- `POST /broadcast {teacher, student}` → ส่ง `{type:'state', state}` ตาม tag

### Task 4: client
TeacherLiveList, TeacherLive (แก้กิจกรรม + ควบคุม), LiveScreen (`/live/:id/screen`), StudentLive (`/live/:id`), แบนเนอร์ใน StudentHome, `useLiveSocket` hook (reconnect + refetch)

### Task 5: E2E `tests/e2e/m4.spec.ts`
ครูสร้างไลฟ์ (โพล + ควิซ) → เริ่ม → นักเรียนเห็นแบนเนอร์ → ตอบโพล → จอแสดงจำนวน → ควิซ → เปิดผล → นักเรียนเห็นเฉลย/EXP → จบไลฟ์
